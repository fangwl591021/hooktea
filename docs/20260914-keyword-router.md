# 母子站關鍵字分流修正

發布識別：`20260914-keyword-router-v2`。

## 分流契約

- 母站保留指令：會員專區／會員中心、會員註冊／註冊／注册／加入會員、會員分享／分享好友／推薦好友／邀請好友、會員打卡／打卡。優先於任何子站可設定活動關鍵字。
- 子站固定 `虎克茶簽到贈點` 執行每日領點，優先於可設定活動卡片和一般贈點關鍵字。
- 其餘依序為子站設定的完整贈點關鍵字、完整活動卡片關鍵字、子站推薦指令、明確綁定輸入；其他文字與非文字事件交給母站。
- 活動卡片不再以子字串攔截其他較長指令。比對保留大小寫、全半形、空白／零寬字元正規化。
- 綁定只接收明確綁定指令、手機、`姓名 名字` 等輸入，不再因有待綁定狀態而吃掉 `我想報名` 或其他母站自訂關鍵字。不變更綁定審核或會員資料。
- 同一個文字若與保留指令衝突，使用保留指令的站別，不向兩站重複投遞同一個 replyToken。

## 執行與安全

先完成逐事件分類，母站轉送及子站處理分別交由 `ctx.waitUntil` 保活。子站不同會員可獨立處理；同一來源的子站事件維持順序。診斷寫入不再阻擋回覆與轉送。綁定候選明確未命中才釋出原事件，且只轉送該候選，不重送整批。

子站執行使用分流時的設定快照，避免第二次讀取設定變更造成已分派的事件被拒絕。

保留入口 LINE HMAC 驗證。全批母站事件保留原始 bytes 與簽章；混合批次僅轉送母站所屬事件並重新簽章。不鏡像轉送 GAS，不在下游結果不明時盲目重試。

## 驗證

- 執行正式 Worker 處理器、實際關鍵字比對器與 HMAC 的 23 項 webhook 回歸測試，網路與儲存使用 mock。
- 使用修正前的 Git HEAD 重跑母站重疊、慢子站阻擋、子字串／待綁定攔截測試，三組皆可重現失敗。
- 另跑商城 20、身分／授權 14、點數／付款／舊 API 23 項回歸測試。
- 應通過 `node --check worker.js`、`git diff --check`、Wrangler 4.102.0 deploy dry-run。

這是事件分流修正，不是母站會員不存在或歷史點數未同步的修復。正式 LINE 端到端回覆仍需以實際訊息驗收；健康端點與本機 mock 不足以證明母站已回覆會員。不以偽造會員事件在正式環境測試贈點。

參考：[LINE webhook 文件](https://developers.line.biz/en/docs/messaging-api/receiving-messages/)、[Cloudflare Worker 最佳實務](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)。
